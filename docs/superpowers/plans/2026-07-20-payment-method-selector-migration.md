# foxy-payment-method-selector: migrate to Base UI design system Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Migrate `foxy-payment-method-selector` (the only element that renders `@foxy.io/design-system` UI components) from the old shadcn/Tailwind-based design system to the new Base UI + styled-components one, and remove Tailwind from `foxy-elements` entirely — including the Stripe/Square/Adyen embed layer and icon layer, which turned out to depend on Tailwind (via a shared DOM-measurement probe in `stripe/style-hooks.ts`) without importing the design system at all.

**Architecture:** The element already mounts a React tree into a `ShadowRoot` (`this.#shadowRootRef`, set up in `element.tsx`'s constructor). That tree gets wrapped in `<StyleSheetManager target={shadowRoot}>` → `<ThemeProvider theme={{tokens: defaultTheme}}>`, both validated working via spikes during design (a plain styled component and, the harder case, a Base UI `Select` with a portaled popup — both inject their styles inside the shadow root correctly when `Select.Portal` is given `container={shadowRoot}`). Every design-system import moves from the old flat shadcn-shaped API (`@foxy.io/design-system/ui/<name>`) to the new namespaced compound API (`@foxy.io/design-system/<name>`, e.g. `Card.Root`/`Card.Content`). Tailwind utility classes are replaced with local `styled-components` primitives declared per file, following the same pattern `foxy-design-system` itself uses (plain `styled.div` for anything without a Base UI primitive backing it).

**Tech Stack:** React 19, TypeScript, `styled-components` 6, `@base-ui/react` 1.6 (via `@foxy.io/design-system`), Vitest + Storybook.

## Global Constraints

- Depends on **both** prior plans landing first: `foxy-design-system`'s `2026-07-20-foxy-elements-prerequisites.md` (produces the new tarball) and this repo's own `2026-07-20-theme-mixin-redesign.md` (this element reads the full `theme-mixin` vocabulary via `ThemeableHTMLElement.themeAttributeNames`/`syncThemeCssVarsToStyle()`, so it needs the new 17-attribute vocabulary in place first).

- Every `@foxy.io/design-system/ui/*` import becomes `@foxy.io/design-system/*` (no `/ui/` segment); every flat named export becomes a namespaced property access (`Card` → `Card.Root`, etc.) per the mapping table in the design spec (`docs/superpowers/specs/2026-07-20-base-ui-design-system-migration-design.md`).
- No Tailwind class, `var(--...)` reference, or DOM-based style probe remains anywhere in `foxy-payment-method-selector`'s own files by the end of this plan (Task 16 removes the package entirely — a stray class surviving would silently do nothing and go unnoticed, so Task 16's grep check is not optional). This scope was discovered in two passes: Tasks 2-7 cover the 6 files that directly render design-system components; Tasks 8-15 cover `stripe/style-hooks.ts` and everything that depends on its DOM-probing (the Stripe/Square embed layer, Adyen's injected stylesheet, and the icon layer) — none of which import the design system directly, which is why a recon based on grepping for `@foxy.io/design-system` imports alone misses them.
