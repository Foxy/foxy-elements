# foxy-payment-button

Submit button element for checkout. Links to a `foxy-payment-method-selector` via that selector's `button` attribute and renders an appropriate label based on the selected payment method and the order total from the checkout API client.

```html
<foxy-payment-method-selector button="pay-btn"></foxy-payment-method-selector>
<foxy-payment-button id="pay-btn"></foxy-payment-button>
```

## Label and enabled state

| Selected option type | Label | Enabled |
|---|---|---|
| None / loading | Pay | No |
| Card (`new-card`, `saved-card`, `card`, `stripe-card-element`, `ach`) — total not yet available | Pay | No |
| Card — total available | Pay $X.XX | Yes |
| `purchase-order` | Place Order | Yes |
| `mollie` | Continue to Mollie | Yes |
| `sezzle` | _(hidden — Sezzle branded button rendered instead)_ | — |
| `klarna` | _(hidden — Klarna branded button rendered instead)_ | — |

## Klarna

When the selected option type is `klarna`, the standard button is hidden and a Klarna branded button is rendered instead. The button uses Klarna's official CSS stylesheet loaded via a `<link>` element scoped to the shadow root:

```
https://js.klarna.com/web-sdk/buttons/payment-button.css
```

The button theme (`theme-dark` / `theme-light`) is picked automatically by reading the `--background` CSS custom property on the element via `getComputedStyle`. A dark background (`oklch` L < 50%, hex luminance < 0.179, or HSL L < 50%) selects `theme-light`; anything lighter selects `theme-dark`. No JavaScript SDK calls are required to display the button; Klarna's authorize/finalize flow is handled separately by `foxy-payment-method-selector`.

## Sezzle

When the selected option type is `sezzle`, the standard button is hidden and the Sezzle SDK's branded button is rendered instead. The Sezzle SDK instance is read from `@foxy.io/sdk/checkout/client` — the Foxy SDK loads the Sezzle script and initializes the instance before dispatching `afterStateChange`, so the instance is always available by the time the button renders.

**Implementation constraints:**

- `sdk.init()` must be called exactly once per SDK instance. The SDK instance is a singleton keyed by public key and config; calling `init()` again on the same instance overwrites previously registered handlers. `foxy-payment-button` guards this with a module-level `WeakSet` so only the first element to encounter a given instance calls `init()`.
- `sdk.renderSezzleButton(containerId)` locates the container via `document.getElementById(containerId)` internally, even though the type signature accepts `HTMLElement | string`. The container div must have a non-empty `id` attribute. Additionally, Sezzle's injected CSS scopes all rules under `#sezzle-smart-button-container`, so the container id must be exactly `sezzle-smart-button-container` for styles to apply.
- Because `init()` can only fire once per instance, only one `foxy-payment-button` per page can register Sezzle checkout lifecycle callbacks (`onClick`, `onComplete`, `onCancel`, `onFailure`). The Sezzle example pages are therefore split into separate `sezzle.default.html` and `sezzle.custom.html` files — one button each — rather than showing both themes on a single page.

## Examples

Run `npm run localdev:examples` and open `examples/sezzle.default.html` or `examples/sezzle.custom.html`. Both read `VITE_SEZZLE_PUBLIC_KEY`; without a real sandbox key the Sezzle SDK loads but the button renders in an unauthenticated state.
