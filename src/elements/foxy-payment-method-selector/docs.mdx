# foxy-payment-method-selector

Payment method selector element that renders available checkout payment options, tracks the selected option, and tokenizes the selected method payload.

Required attributes: none. The element still requires checkout client state to be initialized before it can render payment options and tokenize.

For the <code>paypal_platform</code> gateway, the selector renders the base PayPal option plus the SDK-discovered PayPal-supported methods as first-class entries instead of collapsing them into a generic fallback. See the <strong>Pay Pal Platform</strong> story.

For the <code>adyen_embedded</code> gateway, the selector reads the SDK-initialized Adyen Web instance exposed on <code>@foxy.io/sdk/checkout/client</code> and renders a single Adyen Drop-in selector entry that handles all available Adyen payment methods. Calling <code>tokenize()</code> submits the selected payment method to the Drop-in component and returns <code>&#123;&quot;adyenEmbedded&quot;:&#123;&quot;result&quot;:&#123;...&#125;&#125;&#125;</code>. Adyen Components inherit the selector's foxy-design-system theme tokens through Adyen's documented <code>--adyen-sdk-\*</code> CSS variables, while secured card iframes receive matching font, text, placeholder, and error colors through Adyen's secured-field styles config.

Sezzle is exposed as a first-class selector option. It is a redirect gateway — the backend creates the Sezzle checkout session and handles the redirect. Calling <code>tokenize()</code> on a Sezzle option returns <code>&#123;&quot;requestId&quot;:&quot;…&quot;&#125;</code>, identical to <code>mollie_omnipay</code>.

The <code>stripe_v2</code> gateway takes two steps, because the card is never tokenized for us to send. <code>tokenize()</code> only validates the Payment Element (and lets wallets collect their data), resolving with a bare <code>requestId</code>; the checkout submission that follows names the gateway and carries no payment data at all. The backend answers it with a <code>next_action</code> of type <code>confirm_intent</code>, whose <code>params.client_secret</code> belongs to a PaymentIntent it created but did not confirm. Passing that next action to <code>handleNextAction()</code> confirms it from inside the mounted Payment Element — the only place the card exists — after which the caller resumes the transaction with <code>POST /checkout?action=continue</code>. A resolved <code>handleNextAction()</code> means Stripe has the card, not that the payment succeeded: the outcome is established by that resume leg, server-to-server.

The themed elements in this package support a shared set of theme attributes and properties. Unlike the other themed elements, which each consume only a subset, <code>foxy-payment-method-selector</code> consumes the full shared theme token vocabulary.

If checkout state is initialized but exposes no recognized payment methods, the element renders an unavailable state instead of fabricating a fallback option. In that state, <code>tokenize()</code> rejects because no payment method is selected.

## Scenarios

Every scenario is a story in this sidebar entry. Each one hydrates its own checkout state, so they run against fixtures rather than a live session — no gateway credentials, no sandbox setup, and no network.

Gateway coverage:

- <strong>Standard Card</strong> — a card gateway with a saved card, showing the saved method alongside the option to enter a new one.
- <strong>Standard Ach</strong> — an ACH gateway for a guest customer, with the fields the gateway advertises.
- <strong>Purchase Order</strong> — collects a PO number instead of payment credentials.
- <strong>Standard Redirect</strong> — a redirect gateway that hands the buyer off to the provider.
- <strong>Stripe V 2</strong> and <strong>Stripe Connect Or Charge</strong> — the two Stripe paths, each with a saved payment token.
- <strong>Klarna</strong> — one option per method category the session advertises. Parameterised by buyer market through the <code>Country</code> control.
- <strong>Adyen Embedded</strong> — mounts the Drop-in rather than rendering a radio option.
- <strong>Pay Pal Platform</strong> — the base PayPal entry plus one option per eligible funding source.
- <strong>Sezzle</strong> — a single buy-now-pay-later option, needing no gateway configuration beyond its type.
- <strong>Square Up</strong> — market-dependent method list, also parameterised by <code>Country</code>. Square is the one gateway whose options are derived from <code>format.locale_code</code> rather than from an SDK, so the control changes the list directly.

Behavioural scenarios:

- <strong>Uninitialized</strong> — the empty client state, where <code>tokenize()</code> rejects.
- <strong>Option Selection</strong> — verifies <code>optionIndex</code> reflection and the <code>optionindexchange</code> event.
- <strong>Tokenize From Button</strong> — drives <code>tokenize()</code> from a button the way an integration would.

The Stripe stories read <code>VITE_STRIPE_PUBLISHABLE_KEY</code> first and fall back to <code>VITE_STRIPE_DEMO_PUBLISHABLE_KEY</code>, then to a fixture key, so setting either variable points them at your own Stripe account. The remaining gateways stub the SDK handle the element reads off <code>@foxy.io/sdk/checkout/client</code>, which is what lets Klarna, Adyen, PayPal and Square render offline. Their fixtures are deliberately fixed: in production these lists vary by market and by account, so treat the stories as a view of the element's rendering, not as a source of truth for what a given merchant is eligible for.

The card, Stripe and saved-card scenarios seed a single entry through <code>saved_payment_methods</code>, so each shows the saved-card option alongside the gateway-specific flow.

## Tokenization Payload

<code>tokenize()</code> resolves with one of these payload types. The
<code>tokenizationsuccess</code> event emits the same object as
<code>event.detail.payload</code>.

```ts
    fundingSources?: (
      | "paypal"
      | "paylater"
      | "credit"
      | "venmo"
      | "sepa"
      | "bancontact"
      | "eps"
      | "blik"

type PaymentMethodSelectorGooglePayTokenizePayload = Record<string, never>;
type PaymentMethodSelectorGenericTokenizePayload = Record<string, never>;

type PaymentMethodSelectorTokenizePayload =
  | PaymentMethodSelectorSavedCardTokenizePayload
  | PaymentMethodSelectorNewCardTokenizePayload
  | PaymentMethodSelectorAchTokenizePayload
  | PaymentMethodSelectorStripeCardElementTokenizePayload
  | PaymentMethodSelectorStripePaymentElementTokenizePayload
  | PaymentMethodSelectorPurchaseOrderTokenizePayload
  | PaymentMethodSelectorPayPalPlatformTokenizePayload
  | PaymentMethodSelectorApplePayTokenizePayload
  | PaymentMethodSelectorGooglePayTokenizePayload
  | PaymentMethodSelectorGenericTokenizePayload;
```

Purchase order selections render a single required purchase order number field.
The selector enforces a 32-character maximum and returns the entered value in
the tokenization payload.

PayPal Platform selections return <code>paypalPlatform</code> metadata that identifies the selected PayPal flow. Wallet and alternative payment methods use <code>flow: "buttons"</code> with a single funding source, while PayPal new-card, Apple Pay, and Google Pay use their dedicated flow values.

## Usage Example

```html
<foxy-payment-method-selector
  id="payment-selector"
  lang="en-US"
  option-index="0"
  theme-color-primary="#7A2E86"
  theme-border-radius-sm="0.75rem"
></foxy-payment-method-selector>

<button type="button" id="selector-tokenize">Tokenize Selection</button>

<script type="module">
  import "https://cdn-js.foxy.io/elements@2/foxy-payment-method-selector.js";
  import { client as checkoutClient } from "@foxy.io/sdk/checkout/client";

  const selector = document.querySelector("#payment-selector");
  const selectorTokenizeButton = document.querySelector("#selector-tokenize");

  await checkoutClient.refresh();

  selector.addEventListener("tokenizationsuccess", (event) => {
    console.log("Payment method tokenized", event.detail.payload);
  });

  selector.addEventListener("tokenizationerror", (event) => {
    console.error("Payment method tokenization failed", event.detail.error);
  });

  selectorTokenizeButton.addEventListener("click", async () => {
    const payload = await selector.tokenize();
    console.log("Selector tokenize() result", payload);
```
