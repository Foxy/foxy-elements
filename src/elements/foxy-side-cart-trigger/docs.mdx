# foxy-side-cart-trigger

A merchant drops this element anywhere on their site — a header, a product page, a nav bar — to show the cart's item count and open the sidecart drawer on click. It renders a button with a cart icon, the text "Cart" and a count badge; nothing else needs configuring.

Required attributes: none. It reads the shared `sideCart` singleton from `@foxy.io/sdk/checkout/side-cart` directly, so as soon as it's on the page it reflects whatever that singleton knows.

It accepts `lang`, the locale for its visible label, accessible name and announcement text. It falls back to the page's `<html lang>`, then to `en-US`.

## Layout

The `layout` attribute (and `layout` property) picks what the button shows. The badge shows in every layout once the cart holds at least one item.

| `layout` | Shows |
| --- | --- |
| `default`, or no attribute | Icon and text |
| `icon` | Icon only. The text stays in the DOM, visually hidden. |
| `text` | Text only |

Any other value behaves as `default`. The button's accessible name ("Cart, 3 items") is the same in every layout.

```html
<foxy-side-cart-trigger layout="icon"></foxy-side-cart-trigger>
```

## Styling

The element does not use the design system. It ships plain defaults — a bordered button that inherits the page's font and text color, and a badge in the page's system colors — and exposes every visible node as a CSS part:

| Part | What it is |
| --- | --- |
| `button` | The `<button>` that opens the sidecart. |
| `icon` | The cart icon `<svg>`. Not rendered in the `text` layout. It draws with `currentColor`. |
| `label` | The visible "Cart" text inside the button. Not a part in the `icon` layout, where the text is visually hidden. |
| `badge` | The item count. Not rendered while the count is unknown or `0`. |
| `spinner` | Shown in place of the badge while the count is unknown. Hidden from screen readers. |

```css
foxy-side-cart-trigger::part(button) {
  border: none;
  border-radius: 999px;
  background: #1f2937;
  color: #ffffff;
}

foxy-side-cart-trigger::part(badge) {
  background: #f59e0b;
}
```

The screen-reader announcement region is deliberately not a part: it has to stay visually hidden. Switch the theme in the Storybook toolbar to see the trigger restyled with `::part()`.

## Count states

`sideCart.itemCount` is `null` until the SDK knows the count: on a first visit, before the first cart request returns, or when the iframe has not reported yet. A returning shopper's cached count shows right away.

| Count | Shows | Accessible name |
| --- | --- | --- |
| Not known yet | Spinner | "Cart" |
| `0` | Nothing | "Cart, 0 items" |
| 1 or more | Badge | "Cart, 3 items" |

The spinner stays if the count never loads: when no store domain is set, or when the first cart request fails and the shopper has no cached count.

## Screen readers

Count changes are announced through an `aria-live="polite"` region, but only when the shopper caused them. The first count to arrive after page load, and a cached count the store corrects, are silent: the shopper did nothing on this page. A shopper who clicks "Add to cart" hears the new count.

The accessible name and announcements come from this package's message catalog and use ICU plural rules ("1 item", not "1 items").

## Scenarios

- **Loading** — the count is not known yet: a spinner in place of the badge.
- **Known Count** — a non-zero count renders in the badge, and clicking the trigger calls `sideCart.show()` to open the drawer.
- **Icon Only** and **Text Only** — the other two layouts.

Each story stubs only `sideCart`'s `itemCount` getter (the same singleton a real integration reads); everything else — the button, the badge, the click handler, the live region — is the real element.
