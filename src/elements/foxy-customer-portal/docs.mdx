# foxy-customer-portal

A drop-in customer portal: sign-in, access recovery, self-registration,
temporary-password reset, and account management.

```html
<foxy-customer-portal store-domain="demo"></foxy-customer-portal>
```

## Attributes

| Attribute             | Required | Default                    | Notes                                                                                               |
| --------------------- | -------- | -------------------------- | --------------------------------------------------------------------------------------------------- |
| `store-domain`        | yes      | —                          | `demo` becomes `demo.foxycart.com`; a value with a dot is used as-is, so custom domains work.       |
| `template-set-id`     | no       | —                          | Reserved for payment methods, which this element does not show yet. Setting it has no effect today. |
| `full-name-template`  | no       | `{first_name} {last_name}` | Plain token substitution, not ICU. Use it for salutations or name order.                            |
| `skip-password-reset` | no       | `false`                    | Suppresses the forced reset screen after signing in with a temporary password.                      |
| `lang`                | no       | `en-US`                    | BCP 47. Underscores are normalised to hyphens.                                                      |

The embed origin is not an attribute — it comes from `VITE_EMBED_ORIGIN` at
build time.

## Events

| Event           | Detail                                 |
| --------------- | -------------------------------------- |
| `signin`        | none                                   |
| `signout`       | none                                   |
| `passwordreset` | `{ result: "skipped" \| "completed" }` |

## Sections

The account screen adds one section per resource type. Today that is:

| Section       | Shows                                                                                                                           | Notes                                                                                                                                                                                                                                                                                                                                                                  |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Subscriptions | Every subscription as a card: items, price, frequency, status (including the next payment/start/end date it carries) and any error, with an Active/Inactive toggle. | Active and Inactive are two separate server-side requests, not a client-side filter of one list. Manage opens a dialog for the frequency and next payment date the store allows changing; Cancel, Modify items and Update billing navigate to hosted Foxy pages rather than editing in place. Payments opens a dialog listing that subscription's transaction history. |
| Orders | Every non-subscription-renewal transaction: date, order ID, item summary, status and amount, opening a detail dialog with the full item list, totals and receipt link. | Excludes subscription renewals (shown in the subscription's own Payments dialog) and card-update records. Read-only — there is nothing to edit here. |
| Addresses | Every address as a card: label, name, formatted address, company and phone, with a Badge for default billing/shipping. | Read-only list — no create button, matching the portal's hidden `addresses:actions:create` control. Edit opens a dialog covering every v1 field except the admin-only `ignore-address-restrictions` toggle; changing country resets region. |

## Notes

Session data is stored under a key namespaced by store domain, so two Foxy
stores served from one origin do not share a session.

Self-registration appears only when the store enables it. It requires an
hCaptcha challenge, which loads a script from `js.hcaptcha.com`.
