# foxy-customer-portal

A drop-in customer portal: sign-in, access recovery, self-registration,
temporary-password reset, and account management.

```html
<foxy-customer-portal store-domain="demo"></foxy-customer-portal>
```

## Attributes

| Attribute             | Required | Default                    | Notes                                                                                                                                    |
| --------------------- | -------- | -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `store-domain`        | yes      | —                          | `demo` becomes `demo.foxycart.com`; a value with a dot is used as-is, so custom domains work.                                            |
| `template-set-id`     | no       | store default              | Picks the template set, which decides both the language strings and the locale. Omit it and the store's default set is used. Also reserved for future payment-method editing. |
| `skip-password-reset` | no       | `false`                    | Suppresses the forced reset screen after signing in with a temporary password.                                                           |
| `url-sync`            | no       | `false`                    | Reflects the current account sub-page into the host page's URL (`fc_page`/`fc_id` query params) and drives navigation from Back/Forward. |

The embed origin is not an attribute — it comes from `VITE_EMBED_ORIGIN` at
build time.

`lang` is not an input. The portal takes its language from the template set,
and writes the resolved locale onto its own content instead. Setting `lang` on
the element has no effect on what language it renders.

## Events

| Event           | Detail                                 |
| --------------- | -------------------------------------- |
| `signin`        | none                                   |
| `signout`       | none                                   |
| `passwordreset` | `{ result: "skipped" \| "completed" }` |

## Sections

The account screen adds one section per resource type. Today that is:

| Section       | Shows                                                                                                                                                               | Notes                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Subscriptions       | Every subscription as a card: item thumbnails (with a parent/child breakdown for bundled items), price, frequency, an error alert when `error_message` is set, and an info grid (Last payment — with a View link to that transaction, Start date, Next payment, Cancels/Ended, Subscription ID), with an Active/Inactive toggle. | Active and Inactive are two separate server-side requests, not a client-side filter of one list. Manage opens a page (replacing the account screen's content, with a Back button) for the frequency and next payment date the store allows changing, and that page also lists the subscription's own transaction history; Cancel, Modify items and Update billing navigate to hosted Foxy pages rather than editing in place. |
| Payment history     | Every non-subscription-renewal transaction: date, order ID, item summary, status and amount, with a Receipt link when the order has one, opening a page with the full item list, totals and receipt link.                                                                                                                        | Excludes subscription renewals (shown on the subscription's own page) and card-update records. Read-only — there is nothing to edit here.                                                                                                                                                                                                                                                                                     |
| Billing & Shipping  | A payment-method column showing the customer's single default payment method (read-only), next to a billing/shipping address summary (name and formatted address, or an empty-state message) derived from the default-flagged addresses; the full address list — every address as a card with a Badge for default billing/shipping — still renders below it.                                                                | Read-only list — no create button, matching the portal's hidden `addresses:actions:create` control. Edit opens a page covering every v1 field except the admin-only `ignore-address-restrictions` toggle; changing country resets region.                                                                                                                                                                                     |

## Notes

## Language

Every string comes from the API, at `<store base>/s/customer/language_strings`.
The store's own overrides are already merged in, so a store customizes the
portal by editing its language strings — not by setting attributes. Two
attributes that used to do this job, `full-name-template` and `lang`, are gone.

The customer's name is one of those strings: `portal_header_full_name`,
`{firstName} {lastName}`. Reorder the placeholders for a locale that leads with
the family name, or prefix a salutation.

The portal waits up to 3 seconds for that request on first paint. If it fails,
times out, or the store has no strings for a key, the portal renders that
string's built-in English rather than failing — so a slow or missing endpoint
costs a language, never the portal.

## Notes

Session data is stored under a key namespaced by store domain, so two Foxy
stores served from one origin do not share a session.

Self-registration appears only when the store enables it. It requires an
hCaptcha challenge, which loads a script from `js.hcaptcha.com`.
